**Release Date:** September 1, 2026

## 🌟 Executive Overview
Safe Bloom v1.1.0 replaces the legacy text-based copy/paste encrypted JSON backup and restore workflow with a modern, native **Encrypted Vault File (`.safebloom`)** workflow. Users can now export their full encrypted vault directly into a standalone file, share or save it via the native Android system share sheet, and import/restore it using the system file picker with zero clipboard exposure and full ACID transactional safety.

---

## 🚀 Key Changes & Enhancements in v1.1.0

### 1. 📁 Single-File Encrypted Vault Container (`.safebloom`)
* **Standardized Container Format:** Exports encrypted vault data as a single `.safebloom` file container (`format: "SafeBloomVault"`, `version: 1`, `algorithm: "AES-256-CTR-HMAC-SHA256"`).
* **Zero Plaintext Exposure:** Zero intimate health data (periods, symptoms, notes, cycle statistics) is exposed in plaintext. All sensitive records are encrypted within the payload.
* **Privacy-Preserving Filename Standard:** Standardized naming convention (`SafeBloom-Vault-YYYY-MM-DD.safebloom`) without exposing user identifiers or health metrics in metadata.
* **Backward Compatibility:** Full decryption and restore support retained for legacy `ENCRYPTED_VAULT_V1` backup payloads.

### 2. 📤 Native File Export & Share Sheet Integration
* **Zero-Clipboard Export:** Eliminates clipboard vulnerabilities when backing up sensitive data.
* **Native OS Share Sheet:** Direct integration with `share_plus` allows immediate saving to local device storage, Google Drive, SD cards, or secure device-to-device file transfer.
* **Master Password Protection:** Vault files are secured with PBKDF2-HMAC-SHA256 (20,000 iterations) + AES-256-CTR and authenticated with HMAC-SHA256 before writing to disk.

### 3. 📥 Native System File Picker & Pre-Validation
* **Native System File Picker:** Integrated `file_picker` allows users to select `.safebloom` (or legacy `.json`) backup files directly from their device storage.
* **Pre-Decryption Envelope Validation:** Validates file existence, 10MB size limits, and JSON container structure *before* prompting the user for their password.
* **Constant-Time MAC Authentication:** Authenticates the version, salt, IV, and ciphertext using constant-time comparison (`_constantTimeEquals`) to prevent side-channel timing attacks.

### 4. 🛡️ Strict Schema Domain Validation & Atomic Database Restore
* **Domain Schema Verification:** Validates `UserProfile`, `PeriodEntry`, and `SymptomEntry` fields against clinical domain bounds (e.g. cycle length 10–120 days, period duration 1–30 days, valid flow and symptom enums) prior to database insertion.
* **SQLCipher ACID Atomicity:** Atomic database import ensures existing user data is NEVER cleared or overwritten before the imported file has been fully decrypted and validated. If any step fails, the entire transaction rolls back automatically, leaving the current database completely untouched.

### 5. 🎛️ Settings & Recovery UI Upgrades
* **`SettingsView`:** Redesigned backup/restore action buttons (`EXPORT ENCRYPTED VAULT` and `IMPORT ENCRYPTED VAULT`) with dedicated password creation and unlocking dialogs.
* **`DatabaseRecoveryView`:** Upgraded recovery workflow to support picking and restoring from `.safebloom` vault files.
